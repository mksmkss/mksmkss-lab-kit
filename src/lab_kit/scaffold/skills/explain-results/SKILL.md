# 結果・数値の説明の型

ユーザーは、抽象的・回りくどい説明を嫌う。結果や数値を説明するときは、次の4つを**この順序で**、短く書く。

1. **何をしたくて**: 確かめたかったこと。1〜2文。ユーザー自身の言葉で書く。やったことの紹介ではなく、目的(何を確かめたいか)から始める。
2. **どんな計算をして**: 手順を箇条書きにする。何を何件選び、何と何を比べ、何を引いたか。式の名前ではなく、やった操作を書く。
3. **どんな値が出たか**: 表で並べる。比べる行どうしを隣に置く。表の列の意味は、表の前後で言わなくても分かるようにする。
4. **それは何を意味するか**: 結論を2〜3項目。「だから何が言えるか」と「何はまだ言えないか」を分ける。

## 守ること
- 小見出し(太字)は、上の4つをそのまま使う。
- 「全体に上がり」「寄る」のような、基準の分からない言葉を使わない。何と比べて、何が、いくつからいくつになったかを書く。
- 数値は、何の平均か(何seed、何件)を1回だけ書く。
- 比べる2つの値は、同じ条件のものにする。違う条件の値を `0.13 → 0.51` のように矢印で結ばない。結ぶなら条件を明記する。
- 予想が外れた、前の説明が誤っていた場合は、先頭で訂正してから4つの型に入る。
- 確認していないことは「未確認」と書く。原因の推測は、推測と分かるように書く。
- 長くなるときは、型を崩さずに項目を減らす。説明を足すより、削る。
- 数値は、実際に実行して得た値だけを書く。推定値や記憶は書かない。
- **チャットの返信でも、結果を報告するときは毎回この型を使う。** 途中経過でも、(1) 用語の定義 → (2) 結果の表 → (3) 目的に対して何が言えるか、の順にする。

## 言葉の規則
- 実験中に付けた名前・記号(V2、K=3 など)を、定義なしで使わない。初出で、何をするものかを1文で書く。
- 1つのものに1つの名前を付け、最後まで変えない。集まりは「名前 = 条件(件数)」で定義する(例: 「正解が2つ以上あるデータ(120件)」)。
- 表の見出し・行名・列名にも同じ規則を使う。「今」「1」「判定」のような、定義のない言葉を表に置かない。指標名には、何の値か(0.5 なら何、1.0 なら何)を添える。
- A と B の違いは、違う軸(何を数えるか、どの集まりで平均するか、しきい値の決め方)を行にした表で示す。
- 比喩を使わない。何と何を比べ、何がいくつからいくつになったかを書く。
- 自分の作業手順の言葉(「プールする」「引き直す」など)を、説明なしで使わない。
- 式があるなら残す。計算は、入力 → 変換 → 出力の順に、式を添えて書く。GitHub での書き方は `decision-log` の「数式は LaTeX で書く」。
- 具体例は、1件を通しで使う(最初から分かっていたこと → 正解 → 手法の出力 → 結果)。
- 「上位にいたのか、他が超えたのか」のような二択の質問には、感覚で答えず、順位などを数えて数字で答える。
- 「意味がわからない」と言われたら、言い換えを重ねず、用語の定義と、1件を通した具体例で説明し直す。
